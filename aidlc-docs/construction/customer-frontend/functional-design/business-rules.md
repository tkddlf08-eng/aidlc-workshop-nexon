# Business Rules - Customer Frontend

## 1. 인증 규칙

| Rule ID | 규칙 | 조건 | 동작 |
|---------|------|------|------|
| AUTH-01 | 자동 로그인 | localStorage에 유효한 토큰 존재 | 메뉴 화면으로 직행 |
| AUTH-02 | 토큰 만료 | 토큰 검증 실패 (401) | 저장된 credentials로 재로그인 시도 |
| AUTH-03 | 재로그인 실패 | credentials 무효 | 초기 설정 화면으로 이동 |
| AUTH-04 | 초기 설정 필수 필드 | store_id, table_number, password 모두 필수 | 빈 필드 시 제출 불가 |
| AUTH-05 | 인증 정보 저장 | 로그인 성공 시 | token + credentials를 localStorage에 저장 |

---

## 2. 장바구니 규칙

| Rule ID | 규칙 | 조건 | 동작 |
|---------|------|------|------|
| CART-01 | 최소 수량 | 수량 < 1 | 항목 자동 삭제 |
| CART-02 | 중복 추가 | 이미 장바구니에 있는 메뉴 추가 | 수량 +1 (새 항목 생성 안 함) |
| CART-03 | 금액 계산 | 항목 변경 시 | 총 금액 = Σ(단가 × 수량) 즉시 재계산 |
| CART-04 | 영속성 | 모든 변경 시 | localStorage 자동 동기화 |
| CART-05 | 복원 | 앱 시작/새로고침 시 | localStorage에서 장바구니 복원 |
| CART-06 | 빈 장바구니 주문 불가 | items.length === 0 | 주문하기 버튼 비활성화 |
| CART-07 | 주문 후 클리어 | 주문 성공 시 | state + localStorage 모두 클리어 |

---

## 3. 주문 규칙

| Rule ID | 규칙 | 조건 | 동작 |
|---------|------|------|------|
| ORD-01 | 주문 최소 조건 | 장바구니에 1개 이상 항목 | 주문 가능 |
| ORD-02 | 주문 성공 표시 | API 201 응답 | 주문 번호 표시 + 5초 카운트다운 |
| ORD-03 | 자동 리다이렉트 | 주문 성공 후 5초 경과 | 메뉴 화면으로 자동 이동 |
| ORD-04 | 즉시 이동 | 사용자가 5초 전에 클릭 | 즉시 메뉴 화면으로 이동 가능 |
| ORD-05 | 주문 실패 보존 | API 에러 응답 | 장바구니 내용 유지, 에러 메시지 표시 |
| ORD-06 | 중복 제출 방지 | 주문 확정 버튼 클릭 후 | 버튼 비활성화 (응답 올 때까지) |
| ORD-07 | 추가 주문 | 이전 주문 완료 후 | 새 장바구니로 시작, 같은 세션 유지 |

## 4. 메뉴 조회 규칙

| Rule ID | 규칙 | 조건 | 동작 |
|---------|------|------|------|
| MENU-01 | 기본 화면 | 앱 로그인 후 | 메뉴 화면이 홈 화면 |
| MENU-02 | 카테고리 필터 | 카테고리 선택 시 | 해당 카테고리 메뉴만 표시 |
| MENU-03 | 전체 보기 | 카테고리 미선택 또는 "전체" 선택 | 모든 메뉴 표시 |
| MENU-04 | 이미지 fallback | 이미지 로딩 실패 | 기본 플레이스홀더 이미지 표시 |
| MENU-05 | 정렬 순서 | 메뉴 표시 시 | 서버에서 받은 sort_order 순서 유지 |

## 5. 주문 내역 규칙

| Rule ID | 규칙 | 조건 | 동작 |
|---------|------|------|------|
| HIST-01 | 현재 세션만 | 주문 내역 조회 시 | 현재 활성 세션의 주문만 표시 |
| HIST-02 | 시간 순 정렬 | 주문 목록 표시 | 최신 주문이 상단 |
| HIST-03 | 상태 표시 | 각 주문 | 대기중/준비중/완료 상태 뱃지 표시 |
| HIST-04 | 페이지네이션 | 주문 수 > 페이지 크기 | 다음 페이지 로드 가능 |
| HIST-05 | 빈 상태 | 주문 없음 | "아직 주문이 없습니다" 메시지 표시 |
