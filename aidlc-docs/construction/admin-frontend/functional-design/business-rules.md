# Admin Frontend - 비즈니스 규칙

## 1. 인증 규칙

### BR-AUTH-01: 로그인 필드 유효성
| 필드 | 규칙 |
|------|------|
| 매장 식별자 (storeId) | 필수, 비어있지 않음 |
| 사용자명 (username) | 필수, 비어있지 않음 |
| 비밀번호 (password) | 필수, 비어있지 않음 |

### BR-AUTH-02: 세션 만료 규칙
- 토큰 유효 기간: **16시간** (서버에서 설정)
- 프론트엔드 만료 체크: `expiresAt` 기준으로 타이머 설정
- 만료 시 동작: 즉시 로그아웃 + 로그인 화면 리다이렉트
- API 401 응답 시: 즉시 로그아웃 (토큰 무효화된 경우)

### BR-AUTH-03: 인증 상태 복원
- 앱 시작 시 localStorage에서 토큰 확인
- 토큰 존재 + 만료 전: `/api/auth/me` 호출로 유효성 검증
- 검증 실패: 토큰 삭제 + 로그인 화면

### BR-AUTH-04: 보호된 라우트
- 인증되지 않은 사용자: 모든 `/admin/*` 경로 접근 차단
- 로그인 화면으로 리다이렉트 (원래 경로 기억)
- 로그인 성공 후: 원래 경로로 복귀

## 2. 주문 상태 변경 규칙

### BR-ORDER-01: 상태 전이 규칙 (단방향)
```
PENDING → PREPARING → COMPLETED
```
- 역방향 전이 불가 (COMPLETED → PREPARING ❌)
- 건너뛰기 불가 (PENDING → COMPLETED ❌)
- UI에서 다음 상태 버튼만 활성화

### BR-ORDER-02: 상태별 허용 액션
| 현재 상태 | 허용 액션 | 다음 상태 버튼 텍스트 |
|-----------|-----------|----------------------|
| PENDING | 상태 변경, 삭제 | "준비 시작" |
| PREPARING | 상태 변경 | "완료" |
| COMPLETED | 없음 | (버튼 비활성화) |

### BR-ORDER-03: 주문 삭제 규칙
- 모든 상태의 주문 삭제 가능 (관리자 권한)
- 삭제 전 확인 팝업 필수
- 삭제 후 해당 테이블 총 주문액 자동 재계산

### BR-ORDER-04: 신규 주문 강조 규칙
- SSE로 수신된 신규 주문: **3초간** 시각적 강조 (배경색 변경)
- 강조 후 일반 상태로 복귀
- 강조 중인 주문도 상태 변경/삭제 가능

## 3. 메뉴 관리 규칙

### BR-MENU-01: 메뉴 등록/수정 유효성
| 필드 | 규칙 | 에러 메시지 |
|------|------|-------------|
| 메뉴명 | 필수, 1~50자 | "메뉴명을 입력해주세요" / "50자 이내로 입력해주세요" |
| 가격 | 필수, 0 이상 정수 | "가격을 입력해주세요" / "0 이상의 숫자를 입력해주세요" |
| 카테고리 | 필수 선택 | "카테고리를 선택해주세요" |
| 설명 | 선택, 최대 200자 | "200자 이내로 입력해주세요" |
| 이미지 | 선택, 5MB 이하, jpg/png/webp | "5MB 이하의 이미지 파일만 업로드 가능합니다" |

### BR-MENU-02: 이미지 업로드 규칙
- 허용 형식: JPEG, PNG, WebP
- 최대 크기: 5MB
- 업로드 전 프론트엔드에서 파일 크기/형식 검증
- 업로드 중 프로그레스 표시
- 업로드 실패 시 재시도 가능

### BR-MENU-03: 메뉴 삭제 규칙
- 삭제 전 확인 팝업 필수
- 삭제 시 관련 이미지도 서버에서 정리 (백엔드 처리)
- 삭제 후 목록에서 즉시 제거

## 4. 카테고리 관리 규칙

### BR-CAT-01: 카테고리 유효성
| 필드 | 규칙 | 에러 메시지 |
|------|------|-------------|
| 카테고리명 | 필수, 1~30자 | "카테고리명을 입력해주세요" |
| 카테고리명 | 중복 불가 | "이미 존재하는 카테고리명입니다" |

### BR-CAT-02: 카테고리 삭제 제약
- 해당 카테고리에 메뉴가 1개 이상 존재하면 삭제 불가
- 에러 메시지: "메뉴가 있는 카테고리는 삭제할 수 없습니다. 먼저 메뉴를 이동하거나 삭제해주세요."
- 프론트엔드에서 menuCount > 0이면 삭제 버튼 비활성화 또는 경고

### BR-CAT-03: 순서 변경 규칙
- 드래그앤드롭으로 순서 변경
- 변경 즉시 서버에 저장 (드롭 시 API 호출)
- 실패 시 이전 순서로 롤백

## 5. 테이블 관리 규칙

### BR-TABLE-01: 이용 완료 규칙
- 이용 완료 전 확인 팝업 필수
- 이용 완료 시:
  - 해당 세션의 모든 주문 → `is_archived = true`
  - 테이블 현재 주문 목록 비우기
  - 총 주문액 0으로 리셋
- 이용 완료 후 되돌리기 불가

### BR-TABLE-02: 과거 내역 조회 규칙
- 날짜 필터: 시작일 ≤ 종료일
- 기본 조회 범위: 오늘
- 최대 조회 범위: 제한 없음 (서버 페이지네이션)
- 정렬: 시간 역순 (최신 먼저)

## 6. UI/UX 규칙

### BR-UI-01: 토스트 알림 규칙
- 위치: 우측 상단
- 자동 사라짐: 3초 (기본)
- 에러 토스트: 5초 (더 오래 표시)
- 최대 동시 표시: 3개 (초과 시 가장 오래된 것 제거)
- 수동 닫기 가능 (X 버튼)

### BR-UI-02: 확인 팝업 규칙
- 위험한 작업 (삭제, 이용 완료)에만 사용
- 확인 버튼: 위험 작업은 빨간색 (danger variant)
- 키보드: ESC로 취소, Enter로 확인
- 외부 클릭으로 닫기 가능

### BR-UI-03: 로딩 상태 규칙
- API 호출 중: 해당 영역에 로딩 인디케이터 표시
- 버튼 클릭 후 API 호출 중: 버튼 비활성화 + 스피너
- 전체 페이지 로딩: 스켈레톤 UI 또는 스피너

### BR-UI-04: 반응형 규칙
- 대시보드 그리드: CSS Grid auto-fill, 최소 카드 너비 280px
- 사이드바: 모바일에서 접을 수 있음 (토글)
- 사이드 패널 (Drawer): 너비 400px (모바일에서 전체 너비)

### BR-UI-05: SSE 연결 상태 표시
- 연결됨: 녹색 인디케이터 (헤더에 표시)
- 재연결 중: 노란색 인디케이터 + "재연결 중..." 텍스트
- 연결 끊김 (재연결 실패): 빨간색 인디케이터 + "연결 끊김" 텍스트
