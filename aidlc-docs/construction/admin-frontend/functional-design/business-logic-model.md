# Admin Frontend - 비즈니스 로직 모델

## 1. 관리자 인증 흐름

### 1.1 로그인 프로세스
```
[로그인 화면] → 입력(store_id, username, password)
    → POST /api/auth/admin/login
    → 성공: JWT 토큰 저장 (localStorage) → 대시보드 이동
    → 실패: 에러 메시지 표시 (잘못된 자격 증명 / 계정 잠금)
```

### 1.2 세션 유지 로직
```
앱 초기화 시:
    1. localStorage에서 토큰 확인
    2. 토큰 존재 → 만료 시간 확인
       - 유효: GET /api/auth/me → 인증 상태 복원 → 대시보드
       - 만료: 토큰 삭제 → 로그인 화면
    3. 토큰 없음 → 로그인 화면
```

### 1.3 자동 로그아웃 로직
```
토큰 발급 시점 + 16시간 = 만료 시점
    - 타이머 설정: setTimeout(logout, 남은시간)
    - 만료 5분 전: 경고 토스트 표시 (선택사항)
    - 만료 시: 토큰 삭제 → 로그인 화면 리다이렉트
    - 모든 API 호출 시 401 응답 → 즉시 로그아웃 처리
```

### 1.4 로그아웃 프로세스
```
로그아웃 버튼 클릭 또는 자동 만료:
    1. POST /api/auth/admin/logout (선택적)
    2. localStorage 토큰 삭제
    3. Zustand store 초기화
    4. SSE 연결 해제
    5. 로그인 화면 리다이렉트
```

## 2. 실시간 주문 대시보드

### 2.1 SSE 연결 관리
```
대시보드 마운트 시:
    1. EventSource 생성: GET /api/orders/stream (Authorization 헤더)
    2. 이벤트 리스너 등록:
       - "new_order": 새 주문 추가
       - "order_status_changed": 주문 상태 업데이트
       - "order_deleted": 주문 삭제 반영
       - "table_reset": 테이블 리셋 반영
    3. 연결 끊김 시: 지수 백오프 재연결 (1s, 2s, 4s, 8s... max 30s)

대시보드 언마운트 시:
    1. EventSource.close()
    2. 재연결 타이머 클리어
```

### 2.2 대시보드 데이터 로딩
```
초기 로딩:
    1. GET /api/tables/dashboard → 전체 테이블 현황 로드
    2. 각 테이블별: 테이블 번호, 세션 상태, 주문 목록, 총 주문액
    3. 반응형 그리드 (CSS Grid auto-fill) 배치

실시간 업데이트:
    - SSE 이벤트 수신 → Zustand store 업데이트 → UI 자동 반영
    - 신규 주문: 해당 테이블 카드에 주문 추가 + 시각적 강조 (3초간)
```

### 2.3 주문 상태 변경 흐름
```
상태 변경 버튼 클릭:
    1. 현재 상태 확인 (PENDING → PREPARING → COMPLETED)
    2. 다음 상태 결정 (단방향만 허용)
    3. PATCH /api/orders/{id}/status { status: nextStatus }
    4. 성공: 로컬 상태 즉시 업데이트 (Optimistic Update)
    5. 실패: 롤백 + 에러 토스트 표시
```

### 2.4 주문 상세 보기
```
주문 카드 클릭:
    1. 사이드 패널 (Drawer) 열기 (오른쪽에서 슬라이드)
    2. GET /api/orders/{id} → 주문 상세 데이터 로드
    3. 표시: 주문 번호, 시각, 테이블 번호, 메뉴 목록, 총 금액, 상태
    4. 패널 내에서 상태 변경/삭제 가능
    5. 닫기: X 버튼 또는 외부 클릭
```

## 3. 테이블 관리

### 3.1 테이블 초기 설정 (태블릿)
```
설정 화면 (관리자가 태블릿에서 수행):
    1. 매장 식별자 입력
    2. 테이블 번호 입력
    3. 테이블 비밀번호 입력
    4. POST /api/tables/{id}/setup
    5. 성공: 로그인 정보 localStorage 저장 → 메뉴 화면 이동
    6. 실패: 에러 메시지 표시
```

### 3.2 주문 삭제
```
삭제 버튼 클릭:
    1. 확인 팝업 표시 ("이 주문을 삭제하시겠습니까?")
    2. 확인 → DELETE /api/orders/{id}
    3. 성공: 로컬 상태에서 주문 제거 + 총 주문액 재계산 + 성공 토스트
    4. 실패: 에러 토스트 표시
    5. 취소 → 팝업 닫기
```

### 3.3 테이블 이용 완료
```
"이용 완료" 버튼 클릭:
    1. 확인 팝업 표시 ("테이블 X 이용을 완료하시겠습니까? 주문 내역이 과거 이력으로 이동됩니다.")
    2. 확인 → POST /api/tables/{id}/complete
    3. 성공: 
       - 해당 테이블 주문 목록 비우기
       - 총 주문액 0으로 리셋
       - 성공 토스트 표시
    4. 실패: 에러 토스트 표시
    5. 취소 → 팝업 닫기
```

### 3.4 과거 주문 내역 조회
```
"과거 내역" 버튼 클릭:
    1. 별도 페이지로 이동 (/admin/tables/{id}/history)
    2. GET /api/orders/history?table_id={id}&date_from=&date_to=
    3. 표시: 주문 목록 (시간 역순)
       - 주문 번호, 시각, 메뉴 목록, 총 금액, 이용 완료 시각
    4. 날짜 필터링 (DatePicker)
    5. "돌아가기" 버튼 → 대시보드 복귀
```

## 4. 메뉴/카테고리 관리

### 4.1 카테고리 관리
```
메뉴 관리 페이지 - 좌측 패널 (마스터-디테일):
    - GET /api/categories → 카테고리 목록 로드
    
    추가:
        1. "추가" 버튼 → 인라인 입력 필드 표시
        2. 카테고리명 입력 → 중복 검증 (프론트 + 백엔드)
        3. POST /api/categories → 목록에 추가
    
    수정:
        1. 카테고리 항목 더블클릭 또는 편집 아이콘
        2. 인라인 편집 → PUT /api/categories/{id}
    
    삭제:
        1. 삭제 아이콘 클릭
        2. 해당 카테고리에 메뉴 존재 여부 확인
           - 메뉴 있음: "메뉴가 있는 카테고리는 삭제할 수 없습니다" 에러
           - 메뉴 없음: 확인 팝업 → DELETE /api/categories/{id}
    
    순서 변경:
        - @dnd-kit/core 드래그앤드롭으로 순서 조정
        - 드롭 시 PATCH /api/categories/{id} { sort_order: newOrder }
```

### 4.2 메뉴 관리
```
메뉴 관리 페이지 - 우측 패널:
    - 좌측에서 카테고리 선택 → GET /api/menus?category_id={id}
    
    등록:
        1. "메뉴 추가" 버튼 → 등록 폼 모달 표시
        2. 입력: 메뉴명*, 가격*, 설명, 카테고리*, 이미지
        3. 유효성 검증 (프론트엔드):
           - 메뉴명: 필수, 1~50자
           - 가격: 필수, 0 이상 정수
           - 카테고리: 필수 선택
        4. 이미지 선택 시: 미리보기 표시
        5. POST /api/menus (multipart/form-data)
        6. 성공: 목록 갱신 + 성공 토스트
    
    수정:
        1. 메뉴 항목 "수정" 버튼 → 수정 폼 모달 (기존 데이터 프리필)
        2. 수정 후 PUT /api/menus/{id}
        3. 이미지 변경 시: POST /api/menus/{id}/image
    
    삭제:
        1. "삭제" 버튼 → 확인 팝업
        2. DELETE /api/menus/{id}
        3. 성공: 목록에서 제거 + 성공 토스트
    
    순서 변경:
        - @dnd-kit/core 드래그앤드롭
        - 드롭 시 PATCH /api/menus/{id}/sort { sort_order: newOrder }
```

## 5. 공통 패턴

### 5.1 API 호출 패턴
```
모든 API 호출:
    1. Authorization: Bearer {token} 헤더 자동 첨부 (axios interceptor)
    2. 로딩 상태 관리 (isLoading)
    3. 에러 처리:
       - 401: 자동 로그아웃
       - 403: 권한 없음 토스트
       - 404: 리소스 없음 처리
       - 422: 유효성 검증 에러 → 폼 필드별 에러 표시
       - 500: 일반 에러 토스트
    4. 성공 시: 토스트 알림 (우측 상단)
```

### 5.2 Optimistic Update 패턴
```
주문 상태 변경 등 빈번한 작업:
    1. UI 즉시 업데이트 (낙관적)
    2. API 호출
    3. 실패 시: 이전 상태로 롤백 + 에러 토스트
```

### 5.3 확인 팝업 패턴
```
위험한 작업 (삭제, 이용 완료):
    1. 확인 모달 표시 (제목, 설명, 확인/취소 버튼)
    2. 확인 → 작업 수행
    3. 취소 → 모달 닫기
```
