# 테이블오더 서비스 - 요구사항 문서

## Intent Analysis

| 항목 | 내용 |
|------|------|
| **User Request** | 테이블오더 서비스 구축 (디지털 주문 시스템 플랫폼) |
| **Request Type** | New Project (신규 프로젝트) |
| **Scope Estimate** | Multiple Components (프론트엔드 + 백엔드 + DB) |
| **Complexity Estimate** | Moderate (다수 기능, SSE 실시간 통신 포함) |

---

## 1. 프로젝트 개요

### 1.1 서비스 비전
디지털 주문 시스템을 통해 고객에게는 편리한 주문 경험을, 매장 운영자에게는 효율적인 운영 환경을 제공하는 테이블오더 플랫폼

### 1.2 핵심 가치 제안

**고객 관점**
- 대기 시간 없는 즉시 주문
- 직관적이고 사용하기 쉬운 인터페이스

**매장 운영자 관점**
- 인건비 절감 및 운영 효율성 증대
- 실시간 주문 관리 및 모니터링

**시장 차별화**
- 다양한 업종에 적용 가능한 유연한 구조
- 직관적인 관리자 도구

### 1.3 프로젝트 범위
- **대상**: 단일 매장 전용 시스템
- **규모**: 소규모 매장 (1~10개 테이블)
- **단계**: MVP (Minimum Viable Product)

## 2. 기술 스택 결정

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 고객용 기능 (Customer Interface)

#### FR-C01: 테이블 태블릿 자동 로그인
- 관리자가 1회 초기 설정 (매장 식별자, 테이블 번호, 비밀번호)
- 로그인 정보 로컬 저장 후 자동 로그인
- 별도 고객 인증 절차 없음

#### FR-C02: 메뉴 조회 및 탐색
- 메뉴 화면이 기본(홈) 화면
- 카테고리별 메뉴 분류 및 표시
- 메뉴 상세 정보: 메뉴명, 가격, 설명, 이미지
- 카테고리 간 빠른 이동
- 카드 형태 레이아웃, 터치 친화적 (최소 44x44px)

#### FR-C03: 장바구니 관리
- 메뉴 추가/삭제, 수량 조절
- 총 금액 실시간 계산
- 장바구니 비우기
- 클라이언트 로컬 저장 (새로고침 시 유지)
- 서버 전송은 주문 확정 시에만

#### FR-C04: 주문 생성
- 주문 내역 최종 확인 후 확정
- 주문 성공 시: 주문 번호 표시 → 장바구니 비우기 → 메뉴 화면 자동 리다이렉트 (5초 후)
- 주문 실패 시: 에러 메시지 표시, 장바구니 유지
- 주문 정보: 매장 ID, 테이블 ID, 메뉴 목록(메뉴명, 수량, 단가), 총 금액, 세션 ID

#### FR-C05: 주문 내역 조회
- 현재 테이블 세션 주문만 표시
- 주문 시간 순 정렬
- 주문별: 주문 번호, 시각, 메뉴/수량, 금액, 상태
- 주문 상태: 대기중/준비중/완료 (3단계)
- 주문 상태 실시간 업데이트 (선택사항 - MVP 후순위)
- 이용 완료 처리된 주문 제외
- 페이지네이션 또는 무한 스크롤 지원

### 3.2 관리자용 기능 (Admin Interface)

#### FR-A01: 매장 인증
- 매장 식별자 + 사용자명 + 비밀번호 입력
- JWT 토큰 기반 인증
- 16시간 세션 유지, 이후 자동 로그아웃
- 브라우저 새로고침 시 세션 유지
- 비밀번호 bcrypt 해싱
- 로그인 시도 제한
- 사전 설정된 단일 관리자 계정 (DB 직접 등록)

#### FR-A02: 실시간 주문 모니터링
- SSE (Server-Sent Events) 기반 실시간 업데이트
- 그리드/대시보드 레이아웃 (테이블별 카드)
- 각 테이블 카드: 총 주문액, 최신 주문 미리보기
- 주문 카드 클릭 시 전체 메뉴 목록 상세 보기
- 주문 상태 변경 (대기중 → 준비중 → 완료)
- 신규 주문 시각적 강조 (색상/애니메이션)
- 2초 이내 주문 표시
- 테이블별 필터링 기능

#### FR-A03: 테이블 관리
- **초기 설정**: 테이블 번호/비밀번호 설정, 16시간 세션 생성
- **주문 삭제**: 확인 팝업 → 즉시 삭제 → 총 주문액 재계산
- **테이블 이용 완료**: 확인 팝업 → 주문 내역 과거 이력 이동 → 주문 목록/총액 리셋
- **과거 주문 내역 조회**: 시간 역순, 날짜 필터링, 주문 정보 표시

#### FR-A04: 메뉴 관리
- 메뉴 CRUD (등록/조회/수정/삭제)
- 메뉴 정보: 메뉴명, 가격, 설명, 카테고리, 이미지(S3 업로드)
- 카테고리별 조회
- 메뉴 노출 순서 조정
- 필수 필드 검증, 가격 범위 검증

## 4. 비기능 요구사항 (Non-Functional Requirements)

### NFR-01: 성능
- SSE 실시간 주문 알림: 2초 이내
- 소규모 매장 (1~10 테이블) 동시 처리
- 페이지 로딩: 3초 이내

### NFR-02: 가용성
- 매장 영업 시간 동안 안정적 운영
- 브라우저 새로고침 시 세션/장바구니 유지

### NFR-03: 사용성
- 터치 친화적 UI (최소 44x44px 버튼)
- 직관적 네비게이션
- 명확한 시각적 피드백 (성공/실패)

### NFR-04: 보안 (기본)
- 비밀번호 bcrypt 해싱
- JWT 토큰 인증
- 로그인 시도 제한
- 세션 만료 관리 (16시간)

## 7. 데이터 모델 개요

### 핵심 엔티티
- **Store**: 매장 정보 (단일)
- **Admin**: 관리자 계정 (단일)
- **Table**: 테이블 정보 (1~10개)
- **TableSession**: 테이블 세션 (시작~이용완료)
- **Category**: 메뉴 카테고리
- **Menu**: 메뉴 항목
- **Order**: 주문 (활성 세션의 현재 주문)
- **OrderItem**: 주문 상세 (메뉴별)

### 과거 주문 이력 관리 방식
- Order 테이블에 `is_archived` 플래그와 `archived_at` 타임스탬프로 관리
- 테이블 이용 완료 시: 해당 세션의 모든 주문에 `is_archived = true`, `archived_at = 현재시각` 설정
- 별도 OrderHistory 테이블로 데이터를 이동하지 않음 (단일 테이블 관리로 단순화)
- 고객 화면: `is_archived = false`인 주문만 조회
- 관리자 과거 내역: `is_archived = true`인 주문을 날짜 필터링하여 조회

### 주요 관계
- Store → Table (1:N)
- Table → TableSession (1:N, 현재 활성 세션은 1개)
- TableSession → Order (1:N)
- Category → Menu (1:N)
- Order → OrderItem (1:N)
- Menu → OrderItem (1:N)

## 8. 주문 상태 흐름

```
대기중 (PENDING) → 준비중 (PREPARING) → 완료 (COMPLETED)
```

- 주문 생성 시 기본 상태: 대기중
- 관리자가 상태 변경 수행
- 단방향 흐름 (역방향 불가)

## 9. 테이블 세션 라이프사이클

```
[세션 없음] → 첫 주문 시 세션 시작 → 주문 추가 → ... → 이용 완료 → [세션 종료]
                                                                    ↓
                                                          주문 내역 → OrderHistory 이동
                                                          테이블 리셋 (주문 목록/총액 0)
                                                                    ↓
                                                          [새 세션 대기] → 다음 고객 첫 주문 시 새 세션
```
